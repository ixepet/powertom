# 狗粮场景接入方案

> 对应设计文档 M4 验收:**在公司真实产品里接一个导出场景,设计师改模板不需要开发介入。**
> 版本:v0.1 草案 · 2026-11-17 · 状态:待选型确认

---

## 1. 验收定义(可量化)

狗粮不是"跑通一个 demo",而是"真实业务能一直用下去"。达到以下全部条件才算通过:

| 维度 | 目标 |
| --- | --- |
| 上线场景数 | ≥ 1 个真实业务导出入口(有真实用户在用) |
| 模板改动闭环 | 设计师改模板 → 跑 check → 发布版本,**零代码改动、零发版** |
| 渲染成功率 | ≥ 99.5%(失败全部可归因:数据缺失 / 模板错误 / 环境问题) |
| 耗时 | 20 页以内 deck,P95 ≤ 3s(不含文件上传下载) |
| 错误定位 | 100% 的报错带页码 + 形状名 + 标签,用户/设计师能自查 |
| 人力收益 | 该场景原人工拼页工时下降 ≥ 50%,或从"不能做"变成"能做" |

## 2. 候选场景取舍

| 场景 | 数据可得性 | 模板复杂度 | 复用频率 | 主要风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **A. 成绩分析报告 deck** | 高:分数、班级、指标全是结构化数据,分析服务已产出 | 中:汇报型 deck,与金样本同构 | 高:每次考试 × 每个年级 | 表格/图表绑定暂不支持,需用图片兜底 | **推荐首期** |
| B. 课堂分析复盘 deck | 中:课堂分析结果已有,但结构还在演进 | 中高:含视频截图、时间轴 | 中:每节课 | 数据结构不稳定,模板会频繁改 | 二期 |
| C. 学校月度工作汇报 | 低:大量非结构化文本 | 低 | 低 | 数据靠人填,引擎价值集中在排版 | 不推荐 |

选 A 的理由:它同时满足"数据天然结构化、模板是标准汇报 deck、出图频率高、人工拼页痛感明确"四条,而且 HaiMate 的产品叙事里已经有这个场景(场景四:考试成绩分析),狗粮与产品故事一致,不需要额外造需求。

### 明确不做(首期范围外)

- 表格行级循环(设计文档 §11 待决策 #2)——本场景用"指标卡 + 文字条目 + 图表贴图"绕开
- 图表数据绑定(c:ser 系列值)——图表由分析服务直接出 PNG,PowerTom 只负责贴图
- 页面内局部循环(如一排卡片按数组生成)——不支持,**页内重复元素只能用下标取固定项**,要循环必须整页克隆(见 §3.4)

## 3. 推荐方案:成绩分析报告导出

### 3.1 用户旅程

```text
老师在 HaiMate 里发起「成绩分析」
  → 选考试、选班级、选分析维度
  → 生成分析结果(已有能力)
  → 点「导出汇报 deck」
      → 异步任务:组数据 → PowerTom.render → 存对象存储
      → 工作台里出现一份可下载 / 可预览的 pptx
  → 老师下载后可直接讲,或让设计师改模板后重新导出
```

### 3.2 模板页面清单

> **2026-11-17 真实 deck 校准**:拿到实际在用的《成绩分析报告(初二年级·期末统考)》后,页面清单按真实结构修订为 9 页。
> 真实 deck 见 `spec/fixtures/score_report/`(已脱敏:学校名与学生姓名替换为占位)。

| 页 | 内容 | 形态 | 引擎能力 |
| --- | --- | --- | --- |
| 1 封面 | 标题、副标题、学校、汇报人与日期 | 文本 | 文本标签 + `date` |
| 2 整体表现 | 4 个指标块 + 总评 | 文本 | 固定下标 `kpis[0..3]` |
| 3 班级均分对比 | 8 个班的分数与班级名 + 结论 | 文本排版 / 图表图片 | 文本标签 或 `powertom:image:*` |
| 4 班级成绩明细 | 表头 + 8 班 + 合计 | **表格 10×7** | **表格行循环** `{{classes[].*}}` |
| 5 学科分析 | 8 个学科 + 总分 | **表格 10×6** | **表格行循环** `{{subjects[].*}}` |
| 6 总分分数段分布 | 8 班 × 4 个分数段 | **表格 10×6** | **表格行循环** `{{distribution[].*}}` |
| 7 重点关注学生 | 10 名学生 | **表格 11×5** | **表格行循环** `{{students[].*}}` |
| 8 改进措施 | 3 条措施(含责任与时间) | 文本 | `tips[0..2]` |
| 9 附录 | 统计口径 | 文本 | `{{#if show_appendix}}` |

早期 v1 契约为了绕开表格能力,设计了"每班一页 + 图表 PNG"的 7 页版本(`template_contract.toml` / `template_scaffold.pptx`)。
v2 已按真实 9 页结构落地,与 v1 并存:

- 契约:`examples/score_report/template_contract_v2.toml`
- 样例数据:`examples/score_report/sample_v2.toml`
- 结构脚手架:`examples/score_report/template_scaffold_v2.pptx`(用 `tools/build_score_report_template_v2.rb` 重建)
- 回归:`spec/powertom/score_report_v2_spec.rb`(lint 0/0、9 页、四张表行数、附录开关)

v1 保留为最小闭环与旧回归;新场景一律用 v2。

### 3.3 数据契约(TOML)

模板标签与下面是**一一镜像**关系,`rake powertom:check` 用这份文件对账。
v2 的完整样例见 [examples/score_report/sample_v2.toml](../examples/score_report/sample_v2.toml)(9 页 / 4 张表);下面保留 v1 契约作为最小闭环示例,字段与页面规格见[模板制作单](成绩分析报告模板制作单.md)。

```toml
# 顶层标量必须写在所有 [[数组表]] 之前(TOML 语法规则)
report_title = "2026 学年第一学期期末成绩分析"
school_name = "海思谷实验学校"
exam_name = "期末统考"
report_date = 2026-01-20          # 不加引号,引擎归一化为 Ruby Date

overview_chart = "/srv/powertom/assets/2026-final/overview.png"
class_rank_chart = "/srv/powertom/assets/2026-final/class-rank.png"
subject_chart = "/srv/powertom/assets/2026-final/subject.png"

class_comparison_note = "3 班与 7 班差距缩小到 1.2 分"
subject_note = "物理实验题得分率仅 61%,是本次最明显的短板"

show_appendix = true
data_source = "教务系统期末统考成绩(2026-01-15 导出)"

# 总览指标卡(固定 4 个)
[[kpis]]
label = "平均分"
value = "82.4"
delta = "+1.8"

[[kpis]]
label = "优秀率"
value = "31.2%"
delta = "+2.4pt"

# 班级详情:每项一页
[[classes]]
name = "初二(3)班"
avg_score = "85.1"
rank = "2/12"
weak_subject = "物理"
focus_students = "李明、王小雨"
chart = "/srv/powertom/assets/2026-final/class-3.png"

# 改进建议(固定 5 条,不足由服务端补齐)
[[tips]]
text = "物理实验题失分集中,建议增加两次专题训练"
```

约定:

- **字段由服务端组装**,不直接透传用户输入;图片路径只允许落在受控目录(见 §7 安全)。
- 条数固定的区域(KPI 卡、建议)用下标取固定项,模板评审时肉眼可对账;数量可变的区域(班级页)用 `#each`。
- 日期字段传 `Date`,模板里用 `{{report_date:date.cn}}` 控制呈现。
- **TOML 顺序**:所有顶层标量写在第一个 `[[表]]` 之前;写在数组表之后的键会归属到最后一个数组元素。样例数据已经按此规则编排。

### 3.4 引擎能力对照

| 需求 | 现状 | 处理 |
| --- | --- | --- |
| 文本 / 数字 / 日期格式化 | ✅ | formatter 四族 |
| 一班一页 | ✅ | `#each classes` |
| 图表 | ⚠️ 不绑定数据 | 分析服务出 PNG,模板用 `powertom:image:` 占位贴图 |
| 表格 | ✅ 行/列/区块/条件 | 单级 `[]`、两级 `#rows`、动态列 `#grid`/`#cols`;多行记录与三级结构用配对区块;条件行用 `{{#if}}...{{/if}}` |
| 5 条建议固定版式 | ✅ | `tips[0..4]` |
| 附录页按开关显示 | ✅ | `#if show_appendix` |
| 页内一排卡片按数组生成 | ❌ | 不支持;卡片数量固定,用下标 |
| 服务器字体 | ⚠️ | 镜像内安装思源黑体,否则 PDF 预览与 PPT 字体不一致 |

结论:真实 deck 需要的 4 张表格已由**表格行循环**覆盖(见 `spec/powertom/table_row_loop_spec.rb` 与真实表格回归);
剩余的缺口只有"页内卡片按数组生成"和"图表数据绑定",首期都可以用固定下标 / 图片占位绕开。

### 3.5 系统结构

```text
┌────────────────────────────────────────────────────────────┐
│ HaiMate 服务(Rails)                                        │
│                                                            │
│  ReportDeckJob(异步)                                       │
│    ├─ 1. ReportDataBuilder   结构化数据 → Hash             │
│    ├─ 2. AssetResolver       图表 PNG 落盘到受控目录        │
│    ├─ 3. PowerTom.check      渲染前门禁(可配置阻断/告警)   │
│    ├─ 4. PowerTom.render     模板 + 数据 → RenderResult     │
│    ├─ 5. 上传对象存储        返回下载地址                   │
│    └─ 6. 埋点                耗时/页数/warnings/错误类型    │
│                                                            │
│  模板注册表 report_templates:报告类型 / 版本 / 文件 / 状态   │
└────────────────────────────────────────────────────────────┘
```

### 3.6 模板治理

- 模板文件与样例数据一起版本化:`templates/score_report/v3/template.pptx` + `sample.toml`。
- **发布门禁**:上传新模板 → 自动跑 `powertom:check`(见 §6)→ error 阻断发布,warning 提示设计师。
- 线上任务**锁定模板版本**,新版本发布不影响正在跑的导出;失败可回滚到上一版本。
- 每次升级 gem 或 ruby_pptx,先用全部已发布模板 + 样例数据跑一遍回归(`check` + 渲染 + 页数断言)。

## 4. 分阶段落地

| 阶段 | 内容 | 产出 | 完成判据 |
| --- | --- | --- | --- |
| 0 · 模板改造 | 设计师按规范做 7 页模板,工程侧准备 `sample.toml` | 模板 v1 + 样例数据 | `powertom:check` 0 error |
| 1 · 本地跑通 | Rails 里加 gem,写 `ReportDataBuilder` 与脚本,本地出图 | 一条命令出 deck | PowerPoint 打开无修复提示,内容与数据一致 |
| 2 · 服务化 | 异步任务、对象存储、下载入口、埋点 | 用户可点击导出 | 灰度 1 个年级,成功率 ≥ 99% |
| 3 · 自助闭环 | 模板上传页 + check 门禁 + 版本切换 | 设计师可自发布 | 一次真实模板改动全程零开发介入 |

每个阶段都可独立验收,不追求一次做完。

## 5. 工程改动清单

| 位置 | 改动 |
| --- | --- |
| `Gemfile` | `gem "powertom"`(先走本地 `path:` 或私有源) |
| `app/services/reports/report_data_builder.rb` | 分析结果 → v2 契约 Hash;固定条数(KPI 4 / 措施 3 / 关注学生 10)与数值文案在 builder 完成,日期保留 `Date` 交给 `date` formatter |
| `app/services/reports/deck_exporter.rb` | 封装 `PowerTom.check` + `render` + 上传;统一错误映射 |
| `app/jobs/report_deck_job.rb` | 异步执行、重试策略、失败通知 |
| `config/powertom/templates.yml` | 报告类型 → 模板路径/版本/是否启用 |
| `app/views/...` | 「导出汇报 deck」入口 + 下载列表 |
| `spec/services/reports/deck_exporter_spec.rb` | 用样例数据断言页数、关键文本、表格展开行数 |
| 运维 | 镜像内安装思源黑体;`/srv/powertom/assets` 目录与清理策略 |

**参考实现已就绪**:[examples/score_report/report_data_builder.rb](../examples/score_report/report_data_builder.rb)(`ScoreReport::DataBuilder`),
可直接复制为 `app/services/reports/report_data_builder.rb`。它已经覆盖:

- 固定条数:KPI 恰好 4 个;措施不足 3 条补「暂无」,超过 3 条**报错而不是静默丢弃**;关注学生取前 10 人并在结论里提示"共 N 人";班级/学科/分布为空拒绝出图
- 文案口径:均分 1 位小数、比率 `percent.1`、对比 `+1.8 分` / `+2.3pt` / `+6 人`
- 数据自洽:分数段单行四段合计必须等于该班人数,分布合计必须等于班级人数合计,否则拒绝出图
- 错误可读:`ScoreReport::DataBuilder::Error`,消息直接可给老师看(如「本次分析缺少班级成绩数据」)
- 端到端回归:`spec/powertom/score_report_data_builder_spec.rb` 用分析结果直接渲染 v2 脚手架,断言 9 页与四张表的展开行数

**导出编排参考实现**:[examples/score_report/deck_exporter.rb](../examples/score_report/deck_exporter.rb)(`ScoreReport::DeckExporter`)

```ruby
result = ScoreReport::DeckExporter.new(
  template_path: "templates/score_report/v1/template.pptx",
  uploader: ->(path, key) { oss_client.upload(path, key) },
  template_version: "v1"
).call(data: builder.build)

result.url            # 下载地址
result.slide_count    # 埋点:成品页数
result.duration_ms    # 埋点:耗时
result.warnings       # 埋点:模板质量趋势
```

- 预检:先跑带数据的 `PowerTom.check`;失败时再跑一次不带数据的 check,据此区分模板问题与数据问题(**不靠错误文案猜分类**)
- 错误映射:`DataError`(老师可读,可重试补数据)/ `TemplateError`(找设计师/运维)/ `UploadError`(可重试),都带 `user_message`,原始细节留在 `message` 里给日志
- 生命周期:临时文件 `ensure` 清理;上传器依赖注入,不绑定具体对象存储
- 回归:`spec/powertom/score_report_deck_exporter_spec.rb` 6 例(正常导出/警告透出/数据错误/模板错误/上传失败/关闭预检)

**异步任务参考实现**:[examples/score_report/report_deck_job.rb](../examples/score_report/report_deck_job.rb)(`ScoreReport::ReportDeckJob`)

```ruby
outcome = job.perform(analysis: payload, attempt: 1)
outcome.succeeded?        # => 成功,result 带 url / slide_count / warnings
outcome.retry_scheduled?  # => 按 outcome.retry_in 秒后再入队,attempt + 1
outcome.failed?           # => 终态,已通知,不再重试
```

- 重试策略:**只重试上传失败与渲染兜底失败**,退避 10s / 20s / 40s(封顶 300s);
  数据不完整、模板异常、数据组装失败重试多少次结果都一样,直接终态,避免拖慢给老师的反馈
- 通知:`notifier` 注入,事件 `:succeeded` / `:retrying` / `:failed`,payload 带 `user_message`,可直接接站内信/飞书
- 队列无关:`perform` 返回协议化 Outcome,ActiveJob / Sidekiq 适配器按 `retry_scheduled?` + `retry_in` 再入队即可
- 回归:`spec/powertom/score_report_report_deck_job_spec.rb` 7 例(成功/一次重试成功/退避到上限/数据错误/模板错误/组装异常/真实端到端)

## 6. 门禁与观测

**发布门禁(模板侧)**

```bash
# 结构自检:按契约核对页数 / 形状名 / 标签 / 备注指令 / 图片占位(换场景只换契约)
rake powertom:lint TEMPLATE=templates/score_report/v3/template.pptx \
                   CONTRACT=templates/score_report/v3/template_contract.toml \
                   DATA=templates/score_report/v3/sample.toml

# 数据对账:模板标签 vs 样例数据
rake powertom:check TEMPLATE=templates/score_report/v3/template.pptx \
                    DATA=templates/score_report/v3/sample.toml
```

- error → 阻断发布;warning → 记入模板评审记录(溢出预警必须人工确认一次)。
- 模板契约与模板、样例数据同目录版本化(`template_contract.toml`);改页面规格必须同时改契约,否则 lint 会报"契约外标签 / 缺少形状"。

**运行时观测**

| 指标 | 用途 |
| --- | --- |
| `render_duration_ms`、`slide_count` | 性能回归与容量 |
| `render_warnings_count` | 模板质量趋势(持续偏高说明模板该改) |
| `render_error{class}` | 区分数据问题 / 模板问题 / 环境问题 |
| 模板版本 + gem 版本 | 出问题能定位到"哪版模板 + 哪版引擎" |

## 7. 风险与兜底

| 风险 | 应对 |
| --- | --- |
| **图片路径被伪造,读取服务器任意文件** | 数据只由服务端组装;`AssetResolver` 校验路径必须在受控目录内、扩展名白名单(png/jpg);不接受前端直接传路径 |
| 数据缺字段导致导出失败 | 出图前用 `PowerTom.check` 预检;失败时给老师可读提示("本次分析缺少 XX 数据"),不吞异常 |
| 设计师改坏模板 | check 门禁 + 版本锁定 + 一键回滚;每次发布前用样例数据渲染并人工过一遍 PowerPoint |
| 字体缺失导致排版错位 | 镜像安装思源黑体;模板交付时附带字体清单;PDF 预览同样依赖字体 |
| 长文本溢出画面 | 溢出预警 + 设计师规范(§3)预留 2 倍版面;真实数据跑一遍人工验收 |
| LibreOffice 校验宽于 PowerPoint | 每个模板版本人工用真实 PowerPoint 开一次(设计文档 §5.5 人工清单) |
| ruby_pptx 0.x 升级破坏兼容 | Gemfile 锁版本;升级前跑全部已发布模板的回归 |
| 导出耗时超标 | 先测基线;必要时模板预热/并发限流;超过 P95 目标再优化 |

## 8. 验收清单

- [ ] 模板 v1 通过 `powertom:check`(0 error)

- [ ] 导出入口灰度 1 个年级,成功率 ≥ 99.5%
- [ ] 设计师独立完成一次模板改动(改文案 + 换图 + 调版式)→ 发布 → 线上生效,全程无开发介入
