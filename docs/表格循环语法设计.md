# 表格循环语法设计(嵌套行 / 动态列)

> 状态:**L0 / L1 / L2 均已实现** · 更新于 2026-11-17
> 已实现:L0 简单行循环(`{{数组[].字段}}`)、L1 两级嵌套(`{{#rows 路径}}`)、
> L2 动态列(`{{#grid rows: .. cols: ..}}`)。
> 本文同时明确哪些**暂时不做**。

---

## 1. 现状:简单行循环能做什么

```text
| 班级              | 均分             |
| {{classes[].name}} | {{classes[].avg}} |
| 年级合计           | {{total_avg}}     |
```

- 一行标记 → 按数组克隆;表头/合计行保留;空数组删行
- 一张表一个循环行;不能与页级 `#each` 叠加
- 局限:
  1. **不能嵌套**——"班级 → 学生"这种两级结构无法表达
  2. **列是静态的**——分数段、指标列随考试配置变化时无法生成

## 2. 设计目标与原则

| 目标 | 说明 |
| --- | --- |
| 向后兼容 | 现有 `[]` 语法保持有效,新语法是它的超集 |
| 显式作用域 | 同一单元格里出现父子字段时,不靠猜,路径写全 |
| 单一职责 | 行循环管行,列循环管列;两者可以组合但语义分开 |
| 失败要响 | 标记位置错误、层级超限、合并单元格冲突,一律报错而不是静默降级 |
| 不做通用报表引擎 | 不做分组聚合、排序、公式;这些属于数据侧 |

## 3. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 扩展 `[]` 深度 | `{{groups[].items[].name}}` 用路径本身表达嵌套 | 无需新语法 | 行边界无法从路径推断;"父行/子行"靠什么区分不明确 |
| B. 块指令(推荐) | 用独立标记行 `{{#rows ...}}` 声明层级 | 行边界明确,可读性最好 | 多一类"标记行",设计师需要理解 |
| C. 网格指令 | 角落单元格 `{{#grid rows: .. cols: ..}}` 一次声明二维 | 动态列最自然 | 语法最重,简单场景变啰嗦 |

**结论**:简单场景继续用 `[]`(方案 A 的糖);嵌套与动态列分别用 B / C,且只在真实需求出现时实现。

## 4. 推荐语法

### 4.1 L0:`[]` 简单行循环(已实现,保持)

```text
| {{classes[].name}} | {{classes[].avg}} |
```

### 4.2 L1:`#rows` 两级嵌套行(已实现)

> 实现:`lib/powertom/table_loop.rb`(计划与结构校验)、
> `adapter/ruby_pptx_adapter.rb#expand_table_rows_nested`(行克隆)、
> `binder.rb`(row_scopes 作用域)、`validator.rb`(逐级对账)。
> 回归:`spec/powertom/table_row_loop_nested_spec.rb`(20 例)。

**数据**

```toml
[[groups]]
name = "初二(1)班"
avg = "81.5"

[[groups.items]]
name = "学生A"
total = 398

[[groups.items]]
name = "学生B"
total = 405
```

**模板**

```text
| {{#rows groups}}          |                  |   ← 父行标记(整格只放标记)
| {{groups[].name}}         | {{groups[].avg}} |   ← 父行内容
| {{#rows groups[].items}}  |                  |   ← 子行标记
| {{groups[].items[].name}} | {{groups[].items[].total}} |   ← 子行内容
```

**语义**

1. `{{#rows 路径}}` 必须**独占一行**,放在首列;该行本身不输出。
2. 紧随其后的一行是它的内容行;内容行里的标签用**完整路径**(`groups[].name`),不引入隐式的 `..` 父引用。
3. 子级标记 `{{#rows groups[].items}}` 只能出现在父级内容行之后;渲染顺序:
   ```
   for group in groups:
     render 父内容行(group)
     for item in group.items:
       render 子内容行(group, item)
   ```
4. 只支持**两级**;第三级标记直接报错 `堆叠层级超过 2 级`。
5. 空数组:父级为空 → 父子行全部删除;子级为空 → 只保留父内容行。
6. 与页级 `#each` 仍不叠加。

### 4.3 L2:`#grid` 动态列(已实现)

> 实现:`table_loop.rb`(参数解析与作用域校验)、
> `adapter/ruby_pptx_adapter.rb#expand_grid_columns`(gridCol + 每行单元格克隆)、
> `grid_value.rb`(列键/交叉值,render 与 check 共用)、`binder.rb`(row/col/cell 作用域)。
> 回归:`spec/powertom/table_grid_spec.rb`(26 例)。

**数据**

```toml
[[distribution]]
name = "初二(1)班"
[distribution.counts]
excellent = 17
good = 25
pass = 15
fail = 4

[[distribution]]
name = "初二(2)班"
[distribution.counts]
excellent = 15
good = 25
pass = 14
fail = 7

[[bands]]
key = "excellent"
label = "≥629 优秀"

[[bands]]
key = "good"
label = "555–628"
```

**模板**

```text
| {{#grid rows: distribution cols: bands value: counts}} | {{col.label}} | {{col.label}} | … |
| {{row.name}}                                          | {{cell}}      | {{cell}}      | … |
```

**语义**

1. `{{#grid ...}}` 放在**表头行的第一个单元格**;它声明:
   - `rows`: 行数组(必填)
   - `cols`: 列数组(必填)
   - `value`: 行内取值字段名(可选;省略时用 `row[col.key]`)
2. 表头行里除首格外的单元格是**列模板**:按 `cols` 长度克隆列,单元格内可用:
   - `{{col.label}}` / `{{col.key}}` / `{{col}}`(列项是标量时)
3. 内容行是**行模板**:按 `rows` 长度克隆行,单元格内可用:
   - `{{row.字段}}` 行数据
   - `{{cell}}` 当前行列交叉值;有 `value:` 时等价于 `row[value][col.key]`,否则 `row[col.key]`
4. 列克隆包括:表头格 + 每一行的对应单元格 + `a:gridCol` 宽度。列宽沿用模板列。
5. 空 `cols`:保留首列(行标题)并删除重复列;空 `rows`:删除内容行,保留表头。
6. **不支持合并单元格**(`gridSpan` / `vMerge`):检测到直接报错,提示设计师先拆表。

### 4.4 组合

`#grid` 与 `#rows` 组合属于二维笛卡尔积,语义复杂且真实需求少:**v1 不支持**,同表出现两种标记直接报错。

## 5. 作用域与路径规则

| 位置 | 可用变量 | 解析规则 |
| --- | --- | --- |
| `[]` 简单行 | 行项字段 + 整页数据 | 带 `[]` 的路径相对行项;不带 `[]` 取整页 |
| `#rows` 父行 | `groups[].字段` | 完整路径第一段必须是声明过的数组 |
| `#rows` 子行 | `groups[].items[].字段` | 前缀必须匹配父/子标记,不允许跨级 |
| `#grid` 表头 | `col.*` | 列项作用域 |
| `#grid` 内容行 | `row.*` / `cell` | 行项作用域 + 交叉值 |

错误示例:

- `{{#rows groups}}` 不在首格 / 与内容文字同格 → `行标记必须独占首列单元格`
- 内容行里写 `{{name}}`(缺 `groups[]` 前缀)→ `表格行标签与循环数组不匹配`
- 三级标记 → `堆叠层级超过 2 级`
- 合并单元格参与循环 → `循环区域包含合并单元格,请先拆分`

## 6. 实现草图(供排期参考)

| 步骤 | 改动 |
| --- | --- |
| 1 | `TableLoop` 升级为解析器:识别标记行、构建层级树;`[]` 走同一棵树(降级为单级) |
| 2 | 行展开:现有 `Element#import` 克隆复用;新增"父行 + 子行"两阶段展开 |
| 3 | 列展开:克隆 `a:gridCol` + 每行 `a:tc`;检测 `gridSpan`/`vMerge` 并拒绝 |
| 4 | 绑定:扩展 Binder 作用域为 `row/col/cell` 三个槽位,路径解析优先级固定 |
| 5 | 校验:`check` 对两级数组逐项对账;动态列校验 `cols` 与 `row[value]` 的键一致 |
| 6 | 兼容:`[]` 保持现状;`#rows/#grid` 是新语法,旧模板零改动 |

风险点:列克隆会改变每行的单元格数量,必须同步 `a:tblGrid` 与 `a:tr` 的 `h`、`graphicFrame` 的 `ext`;这部分需要新增一组冻结点测试(参考现有 `table_row_loop_spec`)。

## 7. 暂不做(明确边界)

- 三级及以上嵌套
- 循环区域里的合并单元格
- 分组聚合(按班级小计、跨行求和)——数据侧算好再传
- 列排序/筛选/条件格式
- 页面内局部卡片循环(与表格无关的另一个缺口)
