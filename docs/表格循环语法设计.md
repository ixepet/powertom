# 表格循环语法设计(嵌套行 / 动态列)

> 状态:**L0 / L1 / L2 / v0.2.2 区块语法均已实现** · 更新于 2026-11-17
> 已实现:L0 简单行循环(`{{数组[].字段}}`)、L1 两级嵌套(`{{#rows 路径}}`)、
> L2 动态列(`{{#grid rows: .. cols: ..}}`)、v0.2.0 配对行区块、
> v0.2.1 多列模板列带、v0.2.2 行级 `#if` 条件。
> 本文同时明确哪些**暂时不做**。

---

## 1. 现状:简单行循环能做什么

```text
| 班级              | 均分             |
| {{classes[].name}} | {{classes[].avg}} |
| 年级合计           | {{total_avg}}     |
```

- 一行标记 → 按数组克隆;表头/合计行保留;空数组删行
- 一张表一个循环行;不能与页级 `#each` 叠加
- 局限:
  1. **不能嵌套**——"班级 → 学生"这种两级结构无法表达
  2. **列是静态的**——分数段、指标列随考试配置变化时无法生成

## 2. 设计目标与原则

| 目标 | 说明 |
| --- | --- |
| 向后兼容 | 现有 `[]` 语法保持有效,新语法是它的超集 |
| 显式作用域 | 同一单元格里出现父子字段时,不靠猜,路径写全 |
| 单一职责 | 行循环管行,列循环管列;两者可以组合但语义分开 |
| 失败要响 | 标记位置错误、层级超限、合并单元格冲突,一律报错而不是静默降级 |
| 不做通用报表引擎 | 不做分组聚合、排序、公式;这些属于数据侧 |

## 3. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 扩展 `[]` 深度 | `{{groups[].items[].name}}` 用路径本身表达嵌套 | 无需新语法 | 行边界无法从路径推断;"父行/子行"靠什么区分不明确 |
| B. 块指令(推荐) | 用独立标记行 `{{#rows ...}}` 声明层级 | 行边界明确,可读性最好 | 多一类"标记行",设计师需要理解 |
| C. 网格指令 | 角落单元格 `{{#grid rows: .. cols: ..}}` 一次声明二维 | 动态列最自然 | 语法最重,简单场景变啰嗦 |

**结论**:简单场景继续用 `[]`(方案 A 的糖);嵌套与动态列分别用 B / C,且只在真实需求出现时实现。

## 4. 推荐语法

### 4.1 L0:`[]` 简单行循环(已实现,保持)

```text
| {{classes[].name}} | {{classes[].avg}} |
```

### 4.2 L1:`#rows` 两级嵌套行(已实现)

> 实现:`lib/powertom/table_loop.rb`(计划与结构校验)、
> `adapter/ruby_pptx_adapter.rb#expand_table_rows_nested`(行克隆)、
> `binder.rb`(row_scopes 作用域)、`validator.rb`(逐级对账)。
> 回归:`spec/powertom/table_row_loop_nested_spec.rb`(20 例)。

**数据**

```toml
[[groups]]
name = "初二(1)班"
avg = "81.5"

[[groups.items]]
name = "学生A"
total = 398

[[groups.items]]
name = "学生B"
total = 405
```

**模板**

```text
| {{#rows groups}}          |                  |   ← 父行标记(整格只放标记)
| {{groups[].name}}         | {{groups[].avg}} |   ← 父行内容
| {{#rows groups[].items}}  |                  |   ← 子行标记
| {{groups[].items[].name}} | {{groups[].items[].total}} |   ← 子行内容
```

**语义**

1. `{{#rows 路径}}` 必须**独占一行**,放在首列;该行本身不输出。
2. 紧随其后的一行是它的内容行;内容行里的标签用**完整路径**(`groups[].name`),不引入隐式的 `..` 父引用。
3. 子级标记 `{{#rows groups[].items}}` 只能出现在父级内容行之后;渲染顺序:
   ```
   for group in groups:
     render 父内容行(group)
     for item in group.items:
       render 子内容行(group, item)
   ```
4. 只支持**两级**;第三级标记直接报错 `堆叠层级超过 2 级`。
5. 空数组:父级为空 → 父子行全部删除;子级为空 → 只保留父内容行。
6. 与页级 `#each` 仍不叠加。

### 4.3 L2:`#grid` 动态列(已实现)

> 实现:`table_loop.rb`(参数解析与作用域校验)、
> `adapter/ruby_pptx_adapter.rb#expand_grid_columns`(gridCol + 每行单元格克隆)、
> `grid_value.rb`(列键/交叉值,render 与 check 共用)、`binder.rb`(row/col/cell 作用域)。
> 回归:`spec/powertom/table_grid_spec.rb`(26 例)。

**数据**

```toml
[[distribution]]
name = "初二(1)班"
[distribution.counts]
excellent = 17
good = 25
pass = 15
fail = 4

[[distribution]]
name = "初二(2)班"
[distribution.counts]
excellent = 15
good = 25
pass = 14
fail = 7

[[bands]]
key = "excellent"
label = "≥629 优秀"

[[bands]]
key = "good"
label = "555–628"
```

**模板**

```text
| {{#grid rows: distribution cols: bands value: counts}} | {{col.label}} | {{col.label}} | … |
| {{row.name}}                                          | {{cell}}      | {{cell}}      | … |
```

**语义**

1. `{{#grid ...}}` 放在**表头行的第一个单元格**;它声明:
   - `rows`: 行数组(必填)
   - `cols`: 列数组(必填)
   - `value`: 行内取值字段名(可选;省略时用 `row[col.key]`)
2. 表头行里除首格外的单元格是**列模板**:按 `cols` 长度克隆列,单元格内可用:
   - `{{col.label}}` / `{{col.key}}` / `{{col}}`(列项是标量时)
3. 内容行是**行模板**:按 `rows` 长度克隆行,单元格内可用:
   - `{{row.字段}}` 行数据
   - `{{cell}}` 当前行列交叉值;有 `value:` 时等价于 `row[value][col.key]`,否则 `row[col.key]`
4. 列克隆包括:表头格 + 每一行的对应单元格 + `a:gridCol` 宽度。列宽沿用模板列。
5. 空 `cols`:保留首列(行标题)并删除重复列;空 `rows`:删除内容行,保留表头。
6. **不支持合并单元格**(`gridSpan` / `vMerge`):检测到直接报错,提示设计师先拆表。

### 4.4 组合

`#grid` 与 `#rows` 组合属于二维笛卡尔积,语义复杂且真实需求少:**v1 不支持**,同表出现两种标记直接报错。

## 5. 作用域与路径规则

| 位置 | 可用变量 | 解析规则 |
| --- | --- | --- |
| `[]` 简单行 | 行项字段 + 整页数据 | 带 `[]` 的路径相对行项;不带 `[]` 取整页 |
| `#rows` 父行 | `groups[].字段` | 完整路径第一段必须是声明过的数组 |
| `#rows` 子行 | `groups[].items[].字段` | 前缀必须匹配父/子标记,不允许跨级 |
| `#grid` 表头 | `col.*` | 列项作用域 |
| `#grid` 内容行 | `row.*` / `cell` | 行项作用域 + 交叉值 |

错误示例:

- `{{#rows groups}}` 不在首格 / 与内容文字同格 → `行标记必须独占首列单元格`
- 内容行里写 `{{name}}`(缺 `groups[]` 前缀)→ `表格行标签与循环数组不匹配`
- 三级标记 → `堆叠层级超过 2 级`
- 合并单元格参与循环 → `循环区域包含合并单元格,请先拆分`

## 6. 实现草图(供排期参考)

| 步骤 | 改动 |
| --- | --- |
| 1 | `TableLoop` 升级为解析器:识别标记行、构建层级树;`[]` 走同一棵树(降级为单级) |
| 2 | 行展开:现有 `Element#import` 克隆复用;新增"父行 + 子行"两阶段展开 |
| 3 | 列展开:克隆 `a:gridCol` + 每行 `a:tc`;检测 `gridSpan`/`vMerge` 并拒绝 |
| 4 | 绑定:扩展 Binder 作用域为 `row/col/cell` 三个槽位,路径解析优先级固定 |
| 5 | 校验:`check` 对两级数组逐项对账;动态列校验 `cols` 与 `row[value]` 的键一致 |
| 6 | 兼容:`[]` 保持现状;`#rows/#grid` 是新语法,旧模板零改动 |

风险点:列克隆会改变每行的单元格数量,必须同步 `a:tblGrid` 与 `a:tr` 的 `h`、`graphicFrame` 的 `ext`;这部分需要新增一组冻结点测试(参考现有 `table_row_loop_spec`)。

## 7. 暂不做(明确边界)

- 三级及以上嵌套
- 循环区域里的合并单元格
- 分组聚合(按班级小计、跨行求和)——数据侧算好再传
- 列排序/筛选/条件格式
- 页面内局部卡片循环(与表格无关的另一个缺口)

| 阶段 | 触发条件 | 交付 |
| --- | --- | --- |
| v2.1 嵌套行 ✅ 2026-11-17 | "班级 → 学生"两级结构 | `#rows` 两级 + 结构校验 + 20 例回归 |
| v2.2 动态列 ✅ 2026-11-17 | "分数段/指标列随考试变化" | `#grid` + 列克隆 + 26 例回归 |

# 9. 下一代:通用表格区块 DSL(v0.2 设计稿)

> 目标:把 L0/L1/L2 三种专用语法收敛成一套**可组合的区块语法**,
> 覆盖任意层级、多行记录、行列二维、条件行与多列模板;L0/L1/L2 保持兼容。
>
> **v0.2.0 / v0.2.1 / v0.2.2 已实现**:配对 `#rows` 区块(多行记录、3 级)+ 多列模板 `#cols` 列带
> (可写在区块内)+ `#if` 行级条件。回归:`spec/powertom/table_blocks_spec.rb`(50 例)。

## 9.1 现有语法的四个硬边界

| 边界 | 现状 | 真实诉求举例 |
| --- | --- | --- |
| 行嵌套最多两级 | `#rows` 父/子固定两层 | 年级 → 班级 → 学生;学科 → 知识点 → 题目 |
| 一条记录只能占一行 | 标记行下一行就是唯一的内容行 | 班级行 + 备注行,两行算一条记录 |
| 动态列只有一个模板列 | `#grid` 固定"首列 + 第二列" | 每个学科要"均分 + 得分率"两列 |
| 行循环与列循环互斥 | `#grid` 不能叠加 `#rows` | 班级 × 学科的二维成绩矩阵 |

另外两个隐性限制:行级条件(某条记录不显示)与静态合并单元格(标题行)在循环表里无法表达。

## 9.2 设计目标与非目标

| 目标 | 说明 |
| --- | --- |
| 正交 | 行循环管"纵向重复",列循环管"横向重复",两者可独立使用,也可组合 |
| 区块化 | `{{#rows}} ... {{/rows}}` 包住"一条记录的全部行",不再依赖"下一行"约定 |
| 有界 | 嵌套深度默认上限 3;超过报错,不追求无限递归 |
| 显式作用域 | 继续使用完整路径(`groups[].items[].name`),不引入隐式 `..` 或相对路径 |
| 失败要响 | 配对、层级、列带范围、合并单元格冲突一律报错 |
| 向后兼容 | L0/L1/L2 的模板零改动;新语法是超集 |
| 不做通用报表引擎 | 分组小计、排序、聚合、公式仍归数据侧 |

**明确不做**:透视表式动态行列交叉、按数据生成 `colspan/rowspan`、循环区内的合并单元格、
页级 `#each` 与表格循环叠加、无限层级。

## 9.3 备选方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 继续加参数 | 给 `#rows` 加 `span: 2`,给 `#grid` 加 `cols: 2` | 改动小 | 组合爆炸,`#grid + #rows` 仍无解 |
| B. 单格 JSON 规格 | 在首格写 `{{#table {...}}}` | 表达力最强 | 设计师不可读,错误难定位 |
| C. 备注声明表格结构 | 表格结构写进备注 | 正文干净 | 结构与版面分离,评审困难 |
| D. 区块 DSL(推荐) | `#rows/#if` 独占行,`#cols` 独占列带 | 结构可见、可组合、渐进落地 | 需要新的配对与作用域规则 |

选 D:设计师在版面上能直接看到 "这一块会重复",与现有 L1 的心智模型一致。

## 9.4 推荐语法

### 9.4.1 三个区块

**行区块**(替代 L1 的"下一行"约定,支持一条记录多行):

```text
| {{#rows grades}}                    |                    |
| {{grades[].name}}                   |                    |
| {{#rows grades[].classes}}          |                    |
| {{grades[].classes[].name}}         | {{...avg}}         |   ← 班级记录第 1 行
| {{grades[].classes[].note}}         |                    |   ← 班级记录第 2 行
| {{/rows}}                           |                    |
| {{/rows}}                           |                    |
```

- `{{#rows 路径}}` / `{{/rows}}` 必须**独占整行**(首列放标记,其余单元格留空),自身不输出。
- 两个标记之间的**所有行**就是一条记录的行模板,按数组长度整体克隆。
- 可以嵌套:`{{#rows grades[].classes}}` 写在父区块内部,层级上限 3。
- 空数组:整个区块删除(与现有一致)。

**条件区块**(行级显示/隐藏):

```text
| {{#rows classes}}            |                |
| {{#if classes[].has_data}}   |                |
| {{classes[].name}}           | {{...avg}}     |
| {{/if}}                      |                |
| {{/rows}}                    |                |
```

- `{{#if 路径}} ... {{/if}}` 同样独占整行;为假时删除区块内的所有行。
- 条件区块**只能写在行区块内**,不能嵌套,内部不能放循环或列带标记(需要"记录内再循环"时把条件写在外层)。
- 路径含 `[]` 时按当前循环作用域解析;不含 `[]` 时先看当前行项、再看整页数据(便于 `#if show_note` 这类整页开关)。
- 条件字段缺失视为错误(不会静默当成 false)。

**列带**(多列动态模板):

```text
| 班级 | {{#cols subjects value: scores}}{{col.label}}{{/cols}} |
```

- `{{#cols 路径 [value: 字段1,字段2]}}` / `{{/cols}}` 必须写在同一行的首尾数据列;两标记之间的列就是列模板(可以多列),整体按列项克隆。
- **列带可以写在任意一行**:表头行,或行区块内的任意内容行。
  - 写在行区块内时,声明行会随区块一起克隆,适合"每个分组自带列头"的版式;
  - 列带描述的是表格的**列**,对整张表生效,不是只对所在区块生效。
- 标记之外的首列是固定列;`#cols` 至少要求一个固定列(否则表格只剩动态列,空数组时无法保留结构)。
- 表头单元格继续用 `{{col.label}}` / `{{col.字段}}`;行列交叉值用 `{{cell}}`。
- `value:` 支持逗号分隔的字段列表,与模板列一一对应(如 `value: scores,rates`);只写 1 个字段时所有模板列共用;数量必须为 1 或等于列带宽度。
- 空 `cols`:只保留固定列。

多列模板例子(每个学科"均分 + 得分率"两列):

```text
| 班级 | {{#cols subjects value: scores,rates}}{{col.label}} | {{col.rate_label}}{{/cols}} |
| {{#rows classes}}            |          |          |
| {{classes[].name}}           | {{cell}} | {{cell}} |
| {{/rows}}                    |          |          |
```


列带写在行区块内的例子(每个班级自带一行科目表头):

```text
| {{#rows classes}}            |                |
| {{classes[].name}}           | {{#cols subjects value: scores}}{{col.label}}{{/cols}} |
| {{classes[].name}}           | {{cell}}       |
| {{/rows}}                    |                |
```

### 9.4.2 组合:任意层级 + 二维矩阵

```text
| 班级 | {{#cols subjects value: scores}}{{col.label}}{{/cols}} | 合计 |
| {{#rows classes}}            |          |          |
| {{classes[].name}}           | {{cell}} | {{classes[].total}} |
| {{/rows}}                    |          |          |
```

> 多列模板已实现:`{{#cols subjects value: scores,rates}}{{col.label}} | {{col.rate_label}}{{/cols}}`
> 会把两列作为一个整体按列项克隆,`{{cell}}` 按模板列顺序取 `scores` / `rates`。

展开顺序(固定,写进实现与错误消息):

```text
1. 列带:所有行一起横向克隆(先列,保证每行的单元格数一致)
2. 行区块:由外到内纵向克隆(每次克隆的是"多行记录")
3. 条件区块:按行项求值,删除为假的区块
4. 绑定:此时每个单元格都已有确定的 row / col / cell 作用域
```

先列后行的原因:列克隆会改变每一行的 `a:tc` 数量和 `a:tblGrid` 的列数,必须先做完,
行克隆才能把"已经对齐的整行"当作一个整体复制。

### 9.4.3 作用域与路径

| 位置 | 可用变量 | 解析规则 |
| --- | --- | --- |
| 行区块内容 | `{{父[].子[].字段}}` 完整路径 | 前缀必须匹配某个已声明的行区块 |
| 列带表头 | `{{col.字段}}` / `{{col}}` | 只对列项 |
| 行列交叉单元格 | `{{row.字段}}` / `{{col.字段}}` / `{{cell}}` | row 为当前记录,cell 为交叉值 |
| 静态行/列 | 整页数据 | 与现在一致 |
| `#if` 条件 | 含 `[]` → 循环作用域;否则当前行项 → 整页数据 | 逐项求值 |

**继续只用完整路径**,不引入相对路径:

- 相对路径会与同名整页字段产生隐式遮蔽,校验和渲染容易不一致;
- 完整路径能直接对账数据,错误消息可以给出"期望 `groups[0].items[1].name`";
- 路径长度由层级上限 3 兜底,真实模板可接受。

### 9.4.4 静态内容与合并单元格

- 行区块之外的行 = 静态行(表头、合计、说明),原样保留,可含整页标签。
- 列带之外的列 = 固定列,不参与克隆,可跨所有行保留。
- **允许**静态行/固定列上的合并单元格,但**不允许**合并单元格与列带或行区块相交。
  注意:横跨整行(包含动态列)的标题行会与列带相交,因此动态列场景下不能这样合并,需把标题放到表格外。
- 列带内的列宽按各自的模板列复制;行高按模板行复制。

### 9.4.5 错误消息(新增部分)

| 情况 | 消息 |
| --- | --- |
| 区块未闭合 | `第 N 行的 {{#rows X}} 缺少 {{/rows}}` |
| 多余的闭合标记 | `第 N 行的 {{/rows}} 没有对应的 {{#rows}}` |
| 嵌套超限 | `行区块嵌套超过 3 级(第 N 行)` |
| 标记不独占整行 | `区块标记必须独占整行,其余单元格请留空` |
| 列带越界 | `{{#cols}} 与 {{/cols}} 必须写在同一表头行,且顺序正确` |
| 没有固定列 | `列带至少要保留一列固定列(首列)` |
| 条件块内嵌循环 | `条件区块内不能放循环标记,请调整嵌套顺序` |
| 合并单元格冲突 | `合并单元格不能与列带或行区块相交,请先拆分` |
| 语法混用 | `同一张表不能混用 L0/L1/L2 与区块语法` |

## 9.5 兼容与迁移

| 旧写法 | 新写法 | 策略 |
| --- | --- | --- |
| `{{classes[].name}}`(L0) | 保留 | 单级、单模板行场景继续用 L0,不强制迁移 |
| `{{#rows groups}}` + 下一行(L1) | `{{#rows groups}} ... {{/rows}}` | 同一张表出现 `{{/rows}}` 即视为区块模式;未配对时按 L1 解释(保留一版,文档标记为 legacy) |
| `{{#grid rows: .. cols: ..}}`(L2) | `{{#cols ..}}` + `#rows` 区块 | L2 保留为"两列模板"的语法糖,内部映射到列带 + 单行区块 |
| 不可叠加的 L1 + 列带 | 区块模式下允许组合 | 仅新语法支持 |

**混用判定**:一张表里同时出现 `[]`、`#rows`、`#grid`、`#cols` 中的多种时,
只有区块模式允许 `#rows + #cols`;其余组合一律报错并给出推荐写法。

## 9.6 实现草图

| 步骤 | 改动 |
| --- | --- |
| 1 | `TableLoop` 升级为树形解析:行区块栈、条件区块、列带范围;产出 `{kind: :blocks, ...}` |
| 2 | 新增 `expand_table_row_range(table, frame, start, finish, count)`:整体克隆多行记录 |
| 3 | `expand_grid_columns` 泛化为 `expand_column_band(table, frame, first_col, last_col, count)` |
| 4 | 列扩展不改变行索引,但每行单元格数变化;行区块沿用原行索引,展开前重新定位标记行 |
| 5 | Binder 扩展为"作用域栈":行层级 + col + cell;完整路径前缀匹配沿用现有实现 |
| 6 | 条件区块在行展开之后逐项求值,按行范围删除 |
| 7 | 校验器递归对账:行区块逐项、列带逐列、交叉值逐格;错误带行/列坐标 |
| 8 | 不变量:展开后每行 `tc` 数 == `tblGrid` 列数;`graphicFrame/@cy` 同步 |

**风险点**

- 多行记录克隆 + 列带克隆的顺序错误会导致 `tc` 数与列数不一致,PowerPoint 会要求修复。
  需要一组"结构不变量"测试(参考 `table_row_loop_spec` / `table_grid_spec`)。
- 行区块里的标记行也会被列克隆;必须先剥离标记,再整体删除,避免留下空行。
- 条件区块删除行后,行索引整体位移;绑定作用域必须基于"展开后的行计划",不能再用原表索引。

## 9.7 开放问题

1. 嵌套上限固定 3 还是可配?(建议固定 3,减少误用)
